## 第 3 步：安装 ZCode

ZCode 是**开源**的：`https://github.com/zai-org/ZCode`

安装好后，在本仓库作为 marketplace 添加：

```
1535273240sch-droid/zcode-teamwork
```

安装这两个插件：

| 插件 | 用途 |
| --- | --- |
| `teamwork` | 本体（8 个角色 + 7 个钩子 + 编排引擎） |
| `hook-probe` | **诊断工具**，把 ZCode 发来的每个钩子事件记录下来 |

> `hook-probe` 是关键。它是我们用来探测平台实际行为的探针，不是功能插件。

### ⚠️ 两个必须做的动作

1. **开一个新会话。** ZCode 的钩子配置是**会话启动时快照**的，当前会话不会热加载。
2. **批准钩子信任。** ZCode 对工作区钩子有信任闸门（`workspace_hooks_pending_trust`），
   **未批准前钩子完全不执行**。这一步最容易漏，漏了等于没装。

## 第 5 步：回答这 4 个问题（全部工作的重点）

### Q1 ⭐ 7 个钩子事件是否都真的送达？

**期望值**：

```
SessionStart / UserPromptSubmit / PreToolUse / PermissionRequest
PostToolUse / PostToolUseFailure / Stop
```

**怎么判断**：看 `events.jsonl` 里出现过哪些 `hookEventName`。

**如果只收到一部分** → 说明第三方插件的事件集比内建插件小。这是**重大发现**，必须报告。

### Q2 ⭐⭐ `Stop` + `decision:"block"` 能否真的拦住收尾？

**这是整个项目最核心的机制** —— "没验证就不许说完成"。

```bash
echo '{"mode":"block"}' > .zcode-probe/mode.json
```

然后**开新会话**，让模型回答一句话：

- **如果它被拦住并继续输出** → 机制成立 ✅
- **如果它正常结束** → 机制不成立 ⚠️，需要换实现路径

> 验证完**务必删除** `mode.json`，否则会一直拦。

### Q3 `PreToolUse` 的拒绝与改写是否生效？

```bash
echo '{"mode":"deny"}' > .zcode-probe/mode.json      # 测拒绝
```

让模型写一个文件 —— 应该被拒绝。

```bash
echo '{"mode":"rewrite"}' > .zcode-probe/mode.json   # 测改写
```

让模型写一个文件。**判定方法（已修正）**：探针是把 `_probe_rewritten` 加到
**工具输入参数**上，不是写进文件内容 —— 所以文件里永远不会出现该标记。

正确的判定是**观察工具调用是否报 schema 校验失败**
（`Tool input failed inputSchema validation`），或让模型跑一条简单命令
（如 `ls -la`）看是否被拒收。严格 schema 的工具遇到未知键会整体拒绝，
这本身就是「输入被真实改写」的铁证。

### Q4 `additionalContext` 是否真的进了模型上下文？

```bash
echo '{"mode":"context"}' > .zcode-probe/mode.json
```

开新会话，然后问模型：**"你的上下文里有没有 hook-probe 相关的内容？"**

## ⚠️ 字段名陷阱（务必注意）

代码里用 `pick(input, 'camelCase', 'snake_case')` **同时兼容两种拼写**，因为：

| 来源 | 拼写 |
| --- | --- |
| ZCode 的 **TypeScript 契约** | camelCase：`hookEventName` / `stopHookActive` / `toolInput` |
| **process 钩子的实际载荷** | snake_case：`hook_event_name` / `stop_hook_active` / `tool_input` |

**如果你发现某个钩子「静默失效」**（不报错但也不生效），**第一个要查的就是字段名**。

方法：对比 `first-seen.json` 里的 `keys` 数组，和 `plugins/teamwork/hooks/` 里代码读的键名。

## 第 6 步：端到端跑一轮真实 campaign

真机验证通过后，测完整流程：

```bash
CLI=plugins/teamwork/lib/teamwork-cli.mjs

node $CLI init --objective "给 utils 里的日期解析函数补一组边界测试"
node $CLI decompose                    # 看拆解草稿
node $CLI plan --milestones m.json     # 提交计划
node $CLI approve                      # 批准（此时才允许执行）
node $CLI schedule                     # 看批次
```

然后在 ZCode 里跑 `/teamwork <目标>`，观察这 5 件事：

1. **访谈**是否正常提问
2. **Sentinel 审宪章**是否返回 `CLEARED` / `BLOCKED`
3. **文件独占**是否真的拦住越界写入
4. **验证门禁**是否在缺少验证记录时拦住收尾
5. **派发预算**是否在超出时拒绝
